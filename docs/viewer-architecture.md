# Replay Viewer architecture — extension contract

## Pipeline

```
.replay -> Electron IPC -> Rust Boxcars executable -> raw actor events
                                    |
                             normalized tracks
                                    |
                       timeline state / interpolation
                                    |
                 render layers / future event detectors
```

The renderer must never know how an Unreal/Boxcars attribute is encoded. All state is normalized into canonical world coordinates with X/Y horizontal, Z up, and timestamps in seconds.

## Rendering extension points

- Scene layer: field, arena, goal, camera and lighting
- Actor layer: ball and cars; decoupled from player identities
- Motion layer: trajectory trails, velocity vectors, future acceleration indicators
- Event layer: keyed time markers and spatial annotations generated by independent detectors
- Camera layer: orbit, ball follow, car follow; later freecam and director mode
- Time layer: scrub, fractional playback, frame stepping, speed presets

**Future detectors** must return events with detector name/version, measured times, actor IDs, evidence windows, and confidence. The viewer displays those as optional overlays, rather than attempting to recognize mechanics inside the Three.js render loop.

## Known limitations

The first version uses schematic models, and source-dependent pose interpolation. Actor tracking, raw replication values, player identity and real arena dimensions need verification on multiple Boxcars replay versions. Raw input is untrusted: decoder processes run outside the renderer with a runtime timeout and explicit memory limits planned for later.
